## 题目

马的遍历：给定起点，求到棋盘上每个点的最少步数，不可达输出 `-1`。

标准做法是 BFS，八个方向的马步，第一次到达某个点时的层数就是最短路。

## 我的错误

我写成了这样：

```cpp
queue<pair<int,int>> q;
q.push({sx, sy});
dist[sx][sy] = 0;

while (!q.empty()) {
    auto [x, y] = q.front(); q.pop();

    if (vis[x][y]) continue;   // 出队时才标记
    vis[x][y] = true;

    for (auto [dx, dy] : dirs) {
        int nx = x + dx, ny = y + dy;
        if (inBoard(nx, ny) && dist[nx][ny] == -1) {
            dist[nx][ny] = dist[x][y] + 1;
            q.push({nx, ny});  // 没有标记 vis
        }
    }
}
```

逻辑上"结果是对的"——每个点第一次被赋值时就是最短距离，`vis` 也最终都会是 true。
但提交后 MLE，换小一点的图又过了。

## 为什么错

问题在**同一个点会被重复入队**。

我的判重条件是 `dist[nx][ny] == -1`，看起来能防重复。但 `dist` 是**出队时**才保证自己的
后继扩展只做一次；而入队发生在扩展的那一刻。考虑一个点 `v` 有两个前驱 `a`、`b` 在同一层：

1. 处理 `a` 时，`dist[v] == -1`，赋值并入队 `v`；
2. 处理 `b` 时，`dist[v]` 已经不是 `-1` 了 —— 这一步确实挡住了。

所以真正的问题不是"同一层重复"，而是**队列里存在大量"已经不需要再处理、但还排在队列里"的元素**。
更严重的是我漏掉了一个情况：`dist[x][y] + 1` 在出队时才计算，
如果一个点 `v` 被入队了两次（在我这种写法下确实可能，只要两次入队之间 `dist[v]` 还是 `-1`），
队列长度就会随扩展层数膨胀。

在 400×400 的棋盘上，马步的可达点接近 16 万，
每个点平均被 8 个方向尝试、其中一部分真的入队两次，
队列峰值从"一层宽度"涨到"所有已访问点的数量级"。
`pair<int,int>` 加上 `std::queue` 的节点开销，内存一下就不够了 —— 这就是 MLE 的来源。

**根因是我把"防止重复处理"和"防止重复入队"当成了一件事。**
`vis` 管的是前者，我却在出队时才设置它，于是后者完全没人管。

## 正确逻辑

**在入队的那一刻就标记**，让"入队"和"已发现"成为同一个事件：

```cpp
queue<pair<int,int>> q;
vector<vector<int>> dist(n + 1, vector<int>(m + 1, -1));

q.push({sx, sy});
dist[sx][sy] = 0;              // 起点入队即标记

while (!q.empty()) {
    auto [x, y] = q.front(); q.pop();

    for (auto [dx, dy] : dirs) {
        int nx = x + dx, ny = y + dy;
        if (!inBoard(nx, ny)) continue;
        if (dist[nx][ny] != -1) continue;   // 已经发现过，直接跳过

        dist[nx][ny] = dist[x][y] + 1;      // 赋值 = 标记，两件事合一
        q.push({nx, ny});
    }
}
```

关键是把 `dist[nx][ny] = ...` 当成"标记已发现"来用，而不是当成"记录答案"。
这样每个点最多入队一次，队列峰值回到 O(一层宽度)，内存就正常了。

顺带处理了题目要求的 `-1`：初始化为 `-1`，没被访问到的点自然还是 `-1`，不需要单独的 `vis` 数组。

## 可迁移模式

- **"防止重复处理"和"防止重复入队"是两个不同的不变量。** 前者保证正确性，
  后者保证复杂度。我把它们合并成出队时的一个 `vis`，看起来更"省事"，
  实际上是放弃了对复杂度的控制。
- **入队是一个状态变更点，不是一个"稍后再说"的动作。** 任何"要不要做这件事"的判断，
  都必须在动作发生的那一刻完成，不能推迟到消费时。这和神经网络那篇的
  "入队 ≠ 有资格产生效果"是同一个硬币的两面：那边是入队太早，这边是标记太晚。
- **MLE / TLE 时先看队列和容器的峰值规模，而不是先怀疑算法。** 算法对、结果对、
  但复杂度崩了，通常是这种"重复入队/重复递归"的隐藏放大。
- **初始化值可以直接承担状态语义。** 用 `-1` 表示"未访问"，省掉一个数组，
  也让"漏访问"这类 bug 无处藏身。

## AI 如何帮我

1. **帮我算内存。** 我问它"400×400 的棋盘上这个队列最多多少元素"，
   它没有直接说"你写错了"，而是让我加一行 `q.size()` 的峰值打印。
   峰值一出来，我就知道不是算法问题。
2. **帮我区分两种不变量。** 我一开始坚持"我判了 `dist == -1`，不可能重复入队"，
   它让我写出"`v` 在什么情况下会被 push 两次"的具体时序，
   我写不出来才发现自己错了 —— 这比它直接告诉我答案有效。
3. **帮我写清楚代价。** 结论里那句"队列峰值从一层宽度涨到所有已访问点的数量级"
   是它的措辞，比我原来写的"会变慢"准确得多。

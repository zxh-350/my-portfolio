## 题目

给一个长度为 $n$ 的数组 $a$，按下面的方式排成一串数字：

- 第 1 块：$a_1$
- 第 2 块：$a_1, a_2$
- 第 3 块：$a_1, a_2, a_3$
- ……
- 第 $n$ 块：$a_1, a_2, \dots, a_n$

也就是**第 $i$ 块就是把 $a$ 的前 $i$ 个元素原样再写一遍**。整串一共 $n(n+1)/2$ 个数。

接下来 $q$ 次询问，每次给 $l, r$，求这串数字里第 $l$ 个到第 $r$ 个的和。

## 我的错误

第一版我把整串数字真的"造"出来了，再对它做前缀和：

```cpp
long long m = n * (n + 1) / 2;
vector<long long> a(n);
vector<long long> pre(m + 1);   // ← 问题就在这一行

long long num = 0;
for (int i = 0; i < n; i++)
  for (int j = 0; j <= i; j++) {
    pre[num + 1] = pre[num] + a[j];  // 每次再写一遍 a 的前 i 个元素
    num++;
  }

while (q--) {
  int l, r;
  cin >> l >> r;
  cout << pre[r] - pre[l - 1] << endl;   // 区间和 = 两次前缀相减
}
```

样例全过。提交：**MLE**（内存爆掉）。

## 为什么错

先算数量级：$n = 2\times10^5$ 时，

$$
m = \frac{n(n+1)}{2} \approx 2\times10^{10}
$$
每个 `long long` 8 字节，光存这串数字就要 $1.6\times10^{11}$ 字节 ≈ **160 GB**。
评测机通常 256 MB —— 差了 600 倍。这不是"刚好超一点"，是量级错了。

而且不止空间：

| | 我的第一版 | 题目实际需要 |
| --- | --- | --- |
| 空间 | $O(n^2)$ | $O(n)$ |
| 时间 | $O(n^2)$ 生成 | $O(n + q\log n)$ |

就算内存给够，生成阶段也会 TLE。

**思维上的错误是：把「题目描述的序列」当成「必须物理存在的数组」。**
序列确实有 $n^2$ 个数，但询问只问"前 $x$ 个数的和"——
而前 $x$ 个数的和，根本不需要把那 $x$ 个数存下来。

样例过是因为样例 $n$ 只有几十，完全掩盖了 $n^2$ 的后果。

## 正确逻辑

把序列**按块切开**看结构：

- 第 $i$ 块有 $i$ 个数，且恰好就是 $a$ 的前 $i$ 个元素；
- 前 $i$ 块一共 $\text{num}[i] = i(i+1)/2$ 个数，且 `num` 严格递增 —— **可以二分**；
- 前 $i$ 块的总和 = $\sum_{j=1}^{i} \text{pre}[j]$，也就是"数组前缀和的前缀和"，记作 `pre2[i]`；
- 第 $i$ 块的前 $\text{res}$ 个数之和 = `pre[res]`（就是数组前缀和）。

于是"前 $x$ 个数的和"可以这样算：

1. 二分找到第一个满足 `num[k] ≥ x` 的块 $k$；
2. 前 $k-1$ 块整块加进来：`pre2[k-1]`；
3. 剩下的 `res = x - num[k-1]` 个数落在第 $k$ 块的前 `res` 个位置，即 `pre[res]`；
4. 相加。$x=0$ 时返回 0。

区间询问 = 两次前缀相减：`calc(r) - calc(l-1)`。

```cpp
vector<long long> num(n + 1), pre(n + 1), pre2(n + 1);

for (int i = 0; i < n; i++) {
  int a;
  cin >> a;
  pre[i + 1] = pre[i] + a;              // 数组前缀和
}
for (int i = 1; i <= n; i++) {
  num[i]  = (long long)(1 + i) * i / 2; // 前 i 块的个数
  pre2[i] = pre2[i - 1] + pre[i];       // 前 i 块的总和
}

long long calc(long long x) {
  if (x == 0) return 0;
  long long k = lower_bound(num.begin() + 1, num.begin() + n + 1, x) - num.begin();
  long long res = x - num[k - 1];
  return pre2[k - 1] + pre[res];
}

while (q--) {
  long long l, r;
  cin >> l >> r;
  cout << calc(r) - calc(l - 1) << '\n';
}
```

三个边界我逐个核过：

- `x == 0` 直接返回，否则 `lower_bound` 会因为 `num[0] = 0` 落到 0 号块；
- `k-1` 可能为 0，此时 `pre2[0] = num[0] = 0`，公式仍然成立；
- `res` 落在 $[0, k]$，而 $k \le n$，所以 `pre[res]` 不越界。

复杂度：预处理 $O(n)$，每次询问 $O(\log n)$，总计 $O((n+q)\log n)$，空间 $O(n)$。

## 可迁移模式

- **先估数量级，再决定数组开多大。** 看到 $n(n+1)/2$、$2^n$、$n!$ 这类东西，先代一个 $n$ 进去算。我这次若在写 `vector<long long> pre(m + 1)` 之前代一次 $n=2\times10^5$，就不会动手。
- **「序列 + 前缀和 + 二分定位」是固定三件套。** 只要序列能按块分组、块大小单调递增，就能用"整块前缀和 + 块内前缀和"在 $O(\log n)$ 内回答任意前缀询问。按长度枚举、分段求和的题都能套。
- **区间询问 → 两个前缀相减。** `calc(r) - calc(l-1)` 把区间降成前缀；`l - 1` 是最容易漏的地方。
- **二分找"第一个 ≥ x 的块"，不是"等于 x 的块"。** 用 `lower_bound` 而不是 `upper_bound`，下标差一就是答案差一。
- **样例通过不代表复杂度没问题。** 拿题目上限代入自己的复杂度表达式，是最便宜的自检。

## AI 如何帮我

- 让它算「$n=2\times10^5$ 时 $m$ 是多少、要多少内存」，一眼看到 160 GB —— 这比自己猜"大概会爆"有说服力；
- 让它核 `calc` 的边界（`x == 0`、`k-1 == 0`、`res` 的范围），三个都被明确写出来，我才敢确认公式没差一；
- 让它把我脑子里那句"逆着来、化简"翻译成「按块分组 + 前缀和 + 二分」这套可复用的说法 —— 我原来只觉得"精妙"，说不清为什么精妙。

一点体会：AI 能给结论，但"为什么第一版会爆"必须自己能算。

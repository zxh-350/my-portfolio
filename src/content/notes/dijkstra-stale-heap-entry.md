## 题目

单源最短路模板题，边权非负，点数和边数都在 $10^5$ 量级，
朴素的 $O(n^2)$ 过不去，需要用堆优化 Dijkstra。

## 我的错误

```cpp
priority_queue<pair<int,int>, vector<pair<int,int>>, greater<>> pq;
pq.push({0, s});
dist[s] = 0;

while (!pq.empty()) {
    auto [d, u] = pq.top(); pq.pop();

    // 少了：if (d != dist[u]) continue;

    for (auto [v, w] : g[u]) {
        if (dist[u] + w < dist[v]) {
            dist[v] = dist[u] + w;
            pq.push({dist[v], v});
        }
    }
}
```

我甚至觉得"判 `dist[u] + w < dist[v]`"已经足够安全了，因为松弛条件本身会挡住无效更新。

结果 WA，而且是那种随机性的 WA —— 本地小样例全过，提交挂在几个大数据上。

## 为什么错

关键在于我用的是**懒惰删除**：`dist[v]` 被改小之后，堆里那条旧的 `{旧距离, v}` 我没有删
（堆里也没法高效删）。于是同一个点会在堆里出现多次，每次带着不同的距离值。

`if (d != dist[u]) continue;` 这一行的作用是：**弹出时确认这条记录是不是当前的最优状态**。
我漏了它，后果是弹出 `{旧距离, u}` 时，我拿 `dist[u]`（注意这已经是**新值**了，
因为松弛时更新过）去扩展邻居：

```cpp
// 弹出的 d 是旧值，但 dist[u] 是新值
if (dist[u] + w < dist[v]) { ... }
```

这里的写法有个微妙的差别：我写的是 `dist[u] + w`，用的是新距离，
所以**看起来**结果是对的，甚至还"顺手"多松弛了几次。

但它同时引入了两个问题：

1. **复杂度失去保证。** 一个点被弹出多次，每次都要遍历它的所有出边。
   在特殊构造的图上，同一个点可以被反复入堆，总复杂度退化成接近 $O(m \cdot \text{入堆次数})$。
   这就是我 TLE 的原因。
2. **`d` 被无视意味着我放弃了一个不变量。** Dijkstra 的正确性依赖
   "每次弹出的是当前未确定点中距离最小的那个"。如果我不检查 `d` 是否等于 `dist[u]`，
   就等于允许用一条**已经被更优路径取代的**记录去扩展。
   在使用 `d + w` 的变体写法下这会算错（因为 `d` 是旧的、`u` 的邻居却按旧距离被松弛），
   而使用 `dist[u] + w` 只是碰巧不产生错误答案 —— 靠的是运气，不是逻辑。

我当时的理解错误是：**把"松弛条件"当成了万能的安全网。**
它保证 `dist` 单调不增，但不保证"从堆里弹出的记录是有效的"。

## 正确逻辑

弹出时做一次身份核对，过期记录直接丢弃：

```cpp
while (!pq.empty()) {
    auto [d, u] = pq.top(); pq.pop();

    // 过期记录：不是当前最优状态，丢弃
    if (d != dist[u]) continue;   // 等价于 d > dist[u]

    for (auto [v, w] : g[u]) {
        if (d + w < dist[v]) {    // 用 d，不用 dist[u]
            dist[v] = d + w;
            pq.push({dist[v], v});
        }
    }
}
```

两个改动配套使用：

1. **`if (d != dist[u]) continue;`** —— 让"只有当前有效的状态才能扩展"成为一个显式的不变量。
2. **松弛时用 `d` 而不是 `dist[u]`** —— 保证松弛用的就是这条记录携带的距离。
   两者组合起来，逻辑才自洽：要么这条记录有效（`d == dist[u]`），
   要么它已经被丢弃，不存在"混用新旧值"的状态。

改完复杂度回到 $O((n + m) \log n)$，也不再 TLE。

## 可迁移模式

- **惰性删除的数据结构，消费端必须做有效性核对。** 优先队列、时间轮、
  增量更新的线段树、甚至"标脏后再统一重算"的缓存，都是同一类：
  容器里存在过期元素，取出来第一件事是问"你还是最新的吗"。
- **不变量要在使用的每一处显式成立。** "弹出的记录是最优状态"这件事，
  要么靠代码保证（`if (d != dist[u]) continue`），要么靠注释自欺欺人。
  这和神经网络那篇的结论完全一致 —— **作用点检查**，不是入口检查。
- **同一个量有"旧值/新值"两个版本时，就近取用并保持一致。**
  我混用 `d` 和 `dist[u]` 属于典型的"状态双写"，即使当前恰好正确，
  重构一次就会爆。
- **TLE 且算法明显正确时，先怀疑"重复处理"。** 和 BFS 那篇一样：
  正确性没问题的代码，性能崩溃通常来自同一个元素被处理多次。

## AI 如何帮我

1. **让它扮演"不理解我为什么这么写"的 review。** 我把代码给它，只说"帮我 review 边界"，
   它指出了 `d` 和 `dist[u]` 混用这个我自己完全没意识到的问题 ——
   我以为自己写的是一致的，读代码时眼睛会自动补全。
2. **让它构造能暴露重复入堆的图。** 它给了一个"同一点被多条不同长度路径反复改进"的小图，
   我打印入堆次数后看到同一个点进了 5 次，才相信复杂度真的会炸。
3. **帮我把抽象结论写具体。** "惰性删除要核对有效性"这句话是我自己总结的，
   AI 帮我把三篇笔记串起来：神经网络是入队太早、BFS 是标记太晚、
   这里是出堆不核对 —— 三个错其实是同一个模式的三张脸。

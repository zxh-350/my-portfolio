## 题目

题目本身不复杂，是一道典型的图上传播题。

每个神经元有一个阈值 $U_i$ 和一个状态 $C_i$。输入层的 $C_i$ 由数据给出（题目保证输入层 $C_i > 0$），
其余神经元初始为 $0$。规则是：

- 一个神经元只有在 $C_i > 0$ 时才处于"兴奋"状态；
- 兴奋的神经元沿出边把信号传给后继，后继收到的贡献是 $w \times C_i$；
- 一个神经元收到所有前驱的贡献、并且**总和超过**自己的阈值 $U_i$ 后，才会变成兴奋状态
  （$C_i \leftarrow \sum w \cdot C_{pred} - U_i$）；
- 最后输出所有出度为 $0$ 的神经元状态，如果没有兴奋的输出层神经元就输出 `NULL`。

有向无环，所以第一反应就是拓扑排序，按拓扑序传播一遍。

## 我的错误

我写了这样一段传播逻辑（简化后）：

```cpp
queue<int> q;
for (int i = 1; i <= n; i++) {
    if (indeg[i] == 0) { q.push(i); usable[i] = true; }
}

while (!q.empty()) {
    int u = q.front(); q.pop();
    // 出队时我判了状态：平静的节点不再往下处理
    if (C[u] <= 0) continue;

    for (auto [v, w] : g[u]) {
        // 这里少了同一个判断
        dp[v] += w * C[u];
        if (--indeg[v] == 0) {
            if (dp[v] > U[v]) { C[v] = dp[v] - U[v]; q.push(v); }
            else C[v] = 0;
        }
    }
}
```

我当时的想法是："我在出队时已经 `continue` 掉平静节点了，那能走到下面的节点肯定是兴奋的。"

但这个推理有漏洞，而且漏洞正好被卡住的那 20 分暴露了。

## 为什么错

**关键区别：入队 ≠ 此刻仍然兴奋。**

我在 `C[v] = dp[v] - U[v]` 之后才 `q.push(v)`，看起来是"兴奋了才入队"。但问题出在
`if (--indeg[v] == 0)` 这个条件上，它有两个后果：

1. **只有当一个节点的所有前驱都出队之后，它才会结算。** 在那之前，`C[v]` 还是 `0`，
   而后继节点可能已经被其它路径推进了队列。
2. 更要命的是：**同一个节点 `u` 可能在前驱还没全部处理完时就被别的路径影响到**，
   而 `continue` 只挡住了"出队那一刻"的检查，挡不住"传播时 `C[u]` 已经变了"。

最直接的错误形态是这样的：节点 `u` 先被入队（此时 `C[u] > 0`），
但它的 `C[u]` 会因为后续处理被重算或清零（比如它自己是个被减到负数的中间节点），
当它真正出队准备传播时——我的代码确实 `continue` 了；**但如果传入的贡献是负数呢？**

`dp[to] += w * C[u]` 里的 `C[u]` 只要 `<= 0`，这一项就是 `<= 0`，
本来是"平静神经元不该产生任何影响"，结果变成了**给后继加了一个非正的贡献**。
后继的总和因此被拉低，一个本该兴奋的节点被判定为不兴奋，输出层就少了东西。

我当时对拍的时候没察觉，因为随手造的样例图很简单（一条链），
链上的中间节点恰好都是兴奋的，`C[u] <= 0` 的分支根本没被走到。
比赛数据里有一个"中间节点被减成 0"的图，直接把我从 100 分打回 80 分。

换句话说：**我把"过滤"写成了只在入口处生效的一次性检查，而不是在每个作用点检查的不变量。**

## 正确逻辑

把"平静节点不产生任何影响"这句话，落到**每一个用到 `C[u]` 的地方**：

```cpp
while (!q.empty()) {
    int u = q.front(); q.pop();

    // 不变量：只有兴奋的神经元才能影响后继
    if (C[u] <= 0) continue;
    if (!excited[u]) continue;   // 显式状态位，比用 C 的符号更清楚

    for (auto [v, w] : g[u]) {
        // 作用点也要守住同一个不变量
        if (C[u] > 0) dp[v] += w * C[u];

        if (--indeg[v] == 0) {
            if (dp[v] > U[v]) {
                C[v] = dp[v] - U[v];
                excited[v] = true;
                q.push(v);
            } else {
                C[v] = 0;
                excited[v] = false;
            }
        }
    }
}
```

两个具体改动：

1. **单独维护 `excited[v]` 布尔状态**，而不是每次都用 `C[v] > 0` 反推。
   `C` 是数值，会被别的地方修改（减阈值、置零），拿它当状态标志属于耦合；
   一个显式的状态位让"兴奋/平静"这件事只有一个真源。
2. **在传播动作处再确认一次**。如果选择用 `C[u] > 0` 而不是状态位，
   那这个判断必须出现在**所有**读写 `C[u]` 的地方，不能只在函数开头写一次。

改完再对拍，专门造"中间节点被减到恰好 0"和"中间节点被减成负数"的图，才通过。

## 可迁移模式

这道题教给我的是三个可以直接搬走的模式：

- **入队只代表"待处理"，不代表"有资格产生效果"。** 队列是任务清单，状态位才是权限。
  每次从队列取东西出来，都要重新确认它是否还有资格，而不是假设入队时的判断依然成立。
- **不变量的作用域是"作用点"，不是"入口"。** "X 不能影响 Y"这种约束，
  必须写在真正做影响的那一行，而不是指望入口处的过滤。这是 80 分和 100 分的差距。
- **用布尔状态位承载"语义状态"，不要用数值的符号反推。** 数值会被计算修改，
  语义状态不会被，两者混用就是隐藏 bug 的温床。

同类题都能套：DAG 上的依赖传播、BFS 洪水填充、无权最短路、
"只有当值大于 0 才继续递归"的 DFS —— 只要题面出现"满足某条件才能继续影响别人"，
就要在影响发生的那一行再确认一次。

## AI 如何帮我

这次 AI 的作用分三段，跟"帮我写代码"关系不大：

1. **帮我定位真凶。** 我把 80 分的代码贴过去问"为什么会有节点不兴奋"，
   它没有直接改代码，而是指出：出队时的 `continue` 和我传播时少写的判断**不是同一处**，
   并让我打印"每一次 `dp[v] += w * C[u]` 执行时 `C[u]` 的值"。
   我一跑就看到了负数 —— 定位问题比给答案有用得多。
2. **帮我构造反例。** 我原来只会造链状图。让它帮忙设计"中间节点恰好被减到 0"
   和"一个节点被两条路径先后贡献"的图，一次就把漏洞暴露了。
   这和 AlgoLens 那个项目想做的是同一件事：**让反例看得见**。
3. **帮我把复盘写清楚。** 这篇文章的"为什么错"最初我写得含含糊糊，
   是让它追问"`continue` 到底挡住了哪一刻的状态"才逼我把话说准的。

我特意不让它直接给我完整 AC 代码 —— 那 20 分是"我以为我懂了"的地方，
别人替我改掉，我就永远不知道自己错在哪。

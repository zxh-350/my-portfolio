## 题目

有 $n$ 个车站，分成若干级别。有 $m$ 趟车，每趟车给出它**停靠**的站点（编号递增）。

一趟车经过的区间是 `[最小停靠站, 最大停靠站]`，区间内**没停靠**的车站，说明这趟车只是路过 ——
所以这些路过站的级别**严格低于**该趟车停靠的所有站。

求最少要分多少个级别。

**第一步先认清模型**：这是"偏序关系求最长链"，也就是把"路过站 → 停靠站"建成有向图，求拓扑序上的最长路。
认清这一点之后，剩下的问题全变成**怎么建这张图**。

## 我的错误：第一版，直接两两连边

知道是拓扑之后，我的第一反应很直接：对每趟车，把 `[left, right]` 里**所有非停靠站**和**所有停靠站**两两连边。

```cpp
vector<int> r1 = subtract_set(station, station_1);   // 全集 - 本趟停靠站
for (int u : r1) {
  if (u < left || u > right) continue;
  for (int v : station_1) {
    if (v < left || v > right) continue;
    adj[u].push_back(v);
    in_degree[v]++;
  }
}
```

结果：**80 分，有两个点内存超限**。

## 为什么错：先算边数上界

一趟车里，停靠站和路过站各占一部分。最坏情况是"停靠一半、路过一半"：

$$
\text{每趟车边数} \le \frac{n}{2} \times \frac{n}{2} = \frac{n^2}{4}
$$

$n = m = 1000$ 时代进去：

$$
1000 \times \frac{10^6}{4} = 2.5 \times 10^8 \text{ 条边}
$$

每条边在 `vector<int>` 里占 4 字节，光边就要约 **1 GB**，而内存上限是 125 MB。差一个数量级。

还有第二个问题：**这些边大量重复**。不同车次会给出同样的"路过站 → 停靠站"关系，
重复边不会算错答案（最长路多走几条一样的边不影响），但会
- 白占内存；
- 让 `in_degree` 被重复累加，拓扑排序时要多减很多次。

## 正确逻辑

虚拟站点能大幅解决这个问题 —— 这个方向我当时已经知道。但我**故意先不动结构**，先做一版常数优化。

理由很简单：**如果常数和结构一起改，就分不清是哪一步起了作用。**
而且常数优化改动小、当天就能验证能不能过。

### 第一步：只压常数（第二版，通过）

1. **不构造补集**。原来每趟车都用 `subtract_set` 建一个 `unordered_set` 求差集，
   每次都要分配堆内存、$O(n)$ 插入查询。改成 `inS[]` 布尔标记，读入时打标、处理完清掉，$O(1)$ 判断。

2. **只遍历区间内的站**。原来遍历整个 $1 \sim n$ 再筛，改成直接从 `left` 走到 `right`。

3. **二维 `has[u][v]` 判重**。同一对边只入表一次，内存和 `in_degree` 都不再虚增。

4. 邻接表 + 快读（`ios::sync_with_stdio(false)`）。

```cpp
for (int v : station_1) inS[v] = true;          // 标记停靠站

for (int u = left; u <= right; u++) {           // 只走区间
  if (inS[u]) continue;                          // 路过站才建边
  for (int v : station_1) {
    if (!has[u][v]) {                            // 边只入表一次
      has[u][v] = 1;
      adj[u].push_back(v);
      in_degree[v]++;
    }
  }
}

for (int v : station_1) inS[v] = false;          // 清标记，下趟车复用
```

**这一版通过了（100 分）。**

但要说清楚：第二版**没有消除"遍历所有配对"这件事本身**。
最坏情况内层循环仍然要跑 $2.5\times10^8$ 次，只是重复的不再入表。
它是靠"更少的分配 + 更快的常数 + 实际数据没那么坏"过的，**上界并没有变好**。

想让它真正稳，还是得换结构。

### 第二步：换结构，虚拟站点（第三版）

问题的结构是"**一个集合整体连到另一个集合**"（路过站全体 → 停靠站全体）。
这种关系有标准解法：**中间插一个虚拟点**。

- 每趟车新建虚拟点 $w$；
- 所有路过站 `u → w`，`w → 所有停靠站`。

边数从 $|A| \times |B|$ 变成 $|A| + |B|$：

```cpp
for (int t = 1; t <= m; t++) {
  // ... 读入 station[]，标记 inS[]
  int virt = n + t;                       // 虚拟点编号
  for (int u = left; u <= right; u++) {
    if (inS[u]) continue;
    adj[u].push_back(virt);  in_degree[virt]++;
  }
  for (int v : station) {
    adj[virt].push_back(v);  in_degree[v]++;
  }
}
```

**关键点：虚拟节点不贡献层级。**

真实站点权重记 1，虚拟点记 0，再做最长路：

```cpp
vector<int> w(n + m + 1);
for (int i = 1; i <= n; i++) w[i] = 1;   // 真实站算 1 级，虚拟点默认 0

// 拓扑序上做最长路，入度为 0 的点 dp = w[i]
dp[v] = max(dp[v], dp[u] + w[v]);
```

答案就是 $\max dp$。虚拟点只是"中转"，如果给它也算 1 级，答案就会虚高。

现在边数上界：每趟车 $\le n + n$ 条，总共

$$
2 \times 1000 \times 1000 = 2\times10^6 \text{ 条边}
$$

比第一版少两个数量级，而且**"遍历配对"这个动作本身被消掉了**，不再依赖数据凑巧。

## 可迁移模式

- **优化分两层：常数层和结构层。先做常数，再做结构。** 常数优化改得小、见效快、容易验证；
  结构优化收益大但风险高。先把"能过的版本"拿到手，再换结构，出问题时两边都有参照。
- **但要知道常数优化到底改了什么上界。** 第二版通过不代表它变好了 —— 它的最坏时间还是 $O(n^2)$ 配对。
  这种"靠常数和数据通过"的代码，遇到更坏的数据会再次挂掉。
- **"一个集合整体连到另一个集合" = 虚拟节点。** 出现"每个 $a_i$ 都要连到每个 $b_j$"，就考虑中间插点，把 $|A|\cdot|B|$ 压成 $|A|+|B|$。稠密二部图、区间覆盖、分组依赖都能套。
- **虚拟节点用权重表达语义。** 中转点不代表"一层"，权重设 0，最长路只统计真实层级。
- **重复边用矩阵去重。** `has[u][v]` 一行代码解决两件事：少占内存、`in_degree` 与 `adj` 边数严格一致。
- **别看需求就建集合。** `subtract_set` 每次分配 `unordered_set` 是隐性的 $O(n)$ 堆分配，
  能用布尔标记做的判断，别用集合结构。
- **先算上界再写循环。** 看到"两个集合两两组合"，先写 $|A|\times|B|$ 代上限。$2.5\times10^8$ 一算出来就知道要出事。

## AI 如何帮我

- **帮我把"改进"拆成两层。** 我原本想直接上虚拟站点，是它提醒：先把常数压下来拿到通过，
  再换结构才不会一次改两处、分不清因果。这个顺序后来证明是对的 ——
  第二版通过给了我一个可对比的基准。
- **帮我算三种写法的边数上界**：$2.5\times10^8 \to 10^6 \to 2\times10^6$。
  这个对比让我意识到第二版只是"少入表"，第三版才是真的"不遍历配对"。
- **帮我核虚拟点的权重语义**：我一开始想让虚拟点也当普通点 `+1`，它让我算"虚拟点会不会被算成一层"，
  才发现权重必须分开设。
- **挑出一个隐蔽的命名坑**：第三版里 `int w = n + t;` 遮蔽了外层的 `vector<int> w`。
  当前作用域碰巧不错，但把 `w[i]` 挪进循环体就会静默出错，建议改名 `virt`。

一个体会：AI 擅长给"套路的名字"，但**输入规模、边数上界、内存上限这三个数字必须自己算**；
而"先常数后结构"这种顺序，是它提醒我、我自己验证出来的经验。

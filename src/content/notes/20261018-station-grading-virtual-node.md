## 题目

有 $n$ 个车站，编号 $1 \sim n$，车站分成若干级别。有 $m$ 趟车，每趟车会给出它**停靠**的站点（按编号递增）。
一趟车经过的区间是 `[最小停靠站, 最大停靠站]`，区间内**没停靠**的车站说明这趟车只是路过 ——
所以这些路过站的级别一定**严格低于**该趟车停靠的所有站。

求最少需要划分多少个级别。

本质是：把"停靠站"和"路过站"之间的偏序关系建成图，求最长链（拓扑序上的最长路）。

## 我的错误

第一版我是这样建边的：把每趟车的**所有非停靠站**和**所有停靠站**两两连边。

```cpp
vector<int> r1 = subtract_set(station, station_1);   // 全集 - 本趟停靠站
for (int u : r1) {
  if (u < left || u > right) continue;
  for (int v : station_1) {
    if (v < left || v > right) continue;
    adj[u].push_back(v);
    in_degree[v]++;
  }
}
```

逻辑没错，样例也过，**但 80 分，有两个点内存超限**。

## 为什么错

先算边数上界。一趟车的停靠站最多 $n$ 个中的一部分，路过站也是。最坏情况是"停靠一半、路过一半"：

$$
\text{每趟车边数} \le \frac{n}{2} \times \frac{n}{2} = \frac{n^2}{4}
$$

$n = m = 1000$ 时：

$$
1000 \times \frac{10^6}{4} = 2.5 \times 10^8 \text{ 条边}
$$

每条边在 `vector<int>` 里占 4 字节，光边就约 **1 GB**，而这道题的内存上限是 125 MB。
差了一个数量级，不是"再挤挤就行"。

而且这些边里**大量是重复的**：不同车次会给出同样的 (路过站, 停靠站) 关系。
重复边不会让答案错（最长路上多算几条一样的边没影响），但会：
- 白白占内存；
- 让 `in_degree` 被重复累加，拓扑排序时要多减很多次。

我的思维错误：**看到"两个集合之间两两都要连"就直接嵌套循环，没先算 $|A| \times |B|$ 的量级。**

## 正确逻辑

问题的结构是"**一个集合整体连到另一个集合**"（路过站全体 → 停靠站全体）。
这种关系有个标准解法：**中间加一个虚拟节点**。

- 每趟车新建一个虚拟点 $w$；
- 所有路过站 `u → w`；
- `w → 所有停靠站`。

边数从 $|A| \times |B|$ 变成 $|A| + |B|$。

```cpp
for (int t = 1; t <= m; t++) {
  // ... 读入 station[]
  int w = n + t;                          // 虚拟点
  for (int u = left; u <= right; u++) {
    if (inS[u]) continue;                 // 停靠站跳过
    adj[u].push_back(w);  in_degree[w]++;
  }
  for (int v : station) {
    adj[w].push_back(v);  in_degree[v]++;
  }
}
```

**关键点：虚拟节点不贡献层级。** 真实站点权重记 1，虚拟点记 0，然后求最长路：

```cpp
vector<int> w(n + m + 1);
for (int i = 1; i <= n; i++) w[i] = 1;    // 真实站 1 级

// 拓扑序上做最长路
dp[i] = w[i];                             // 入度为 0 的起点
dp[v] = max(dp[v], dp[u] + w[v]);         // 每经过一个真实站 +1，经过虚拟点 +0
```

答案就是 $\max dp$。虚拟点只是"中转"，如果给它也算 1 级，答案就会虚高。

现在边数上界：每趟车 $\le n + n$ 条，总共

$$
2 \times 1000 \times 1000 = 2\times10^6 \text{ 条边}
$$

比第一版少了**两个数量级**，内存和时间都稳稳过。

## 可迁移模式

- **"一个集合整体连到另一个集合" = 虚拟节点。** 只要出现"每个 $a_i$ 都要连到每个 $b_j$"，就考虑中间插一个节点，把 $|A|\cdot|B|$ 压成 $|A|+|B|$。稠密二部图、区间覆盖、分组依赖都能套。
- **虚拟节点用权重表达语义。** 中转点本身不代表"一层"，就把它的权重设 0，让最长路只统计真实层级。权重是给虚拟点"脱敏"的最干净手段。
- **重复边要用矩阵/标记去重。** `has[u][v]` 一行代码就避免同一对边被 push 多次，`in_degree` 也不会虚增。
- **先算上界再写循环。** 嵌套循环出现"两个集合两两组合"时，先写 $|A|\times|B|$，代题目上限。$2.5\times10^8$ 这个数字一算出来，就该知道这条路走不通。
- **优化的顺序也很重要：先做常数级优化（去重、标记数组），再换算法级结构（虚拟点）。** 我第二版先去重，确认内存问题缓解了，才敢引入虚拟点 —— 否则一次改两处，出错都不知道是哪一步。

## AI 如何帮我

- **给方向，但要求我先算账。** "两个集合整体相连 → 加虚拟点"这个套路是它提醒的，但真正说服我的是把三种写法的边数算出来对比：$2.5\times10^8 \to 10^6 \to 2\times10^6$。方向能猜，数量级必须自己算。
- **帮我核权重语义。** 我一开始想把虚拟点也当普通点，dp 直接 `+1`，它让我算"虚拟点会不会被算成一层"，才意识到权重必须分开设。
- **帮我挑出隐蔽的命名坑。** 第三版里 `int w = n + t;` 把外层的 `vector<int> w` **遮蔽**了：循环体内 `w` 是虚拟点编号，循环外 `w[i]` 又是权重。当前写法碰巧没出错（作用域刚好不重叠），但这种同名遮蔽一旦挪动代码就会变 bug，它建议改名成 `virt`。
- **提醒我`in_degree` 的除零/漏减。** 去重之后每一对边只 push 一次，`in_degree` 才和 `adj` 里的边数严格对得上；否则拓扑排序会把点误判成"没处理完"。

一个体会：AI 很擅长给"标准套路的名字"，但**输入规模、边数上界、内存上限这三个数字必须自己算**。
这次 80 分到 100 分之间差的不是算法，是我有没有在写循环之前先估一遍量级。
